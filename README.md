# CS2 Assistant

Личный офлайн-справочник Counter-Strike 2 для Windows. Самостоятельное приложение на Electron + React + TypeScript: без сервера, аккаунта и облачной базы. При первом запуске библиотека пустая — наполнение добавляет пользователь.

![Главный экран CS2 Assistant](docs/screenshots/home.png)

## Запуск

Готовая программа: `release/CS2-Assistant-0.2.0-portable.exe` после сборки. Для её запуска Node.js и интернет не нужны. Приложение не требует установки; библиотека хранится в профиле Windows, а не рядом с EXE. Для переноса библиотеки используйте экспорт/импорт.

Запуск из исходников (Node.js 22.22+):

```powershell
npm ci
npm start
```

При первой установке зависимостей и загрузке Electron нужен интернет. `npm start` собирает интерфейс и открывает обычное окно программы, без локального сервера.

Собрать portable EXE:

```powershell
npm run dist
```

После push GitHub Actions также собирает Windows-приложение. Скачать его можно в **Actions → Check and build → Artifacts → CS2-Assistant-Windows**. EXE не хранится в Git. Сборка не подписана сертификатом разработчика.

Упаковка выполняется во временной папке Windows, затем результат копируется в `release/`: это обходит блокировки промежуточных файлов синхронизатором OneDrive.

## Что реализовано

- Карты: Dust 2, Mirage, Nuke, Ancient, Inferno, Anubis, Cache.
- На каждой карте: смоки, HE-гранаты, флешки, молотовы, лайнапы, позиции, тактики и полезные фишки.
- Переходы: карта → категория → карточки → просмотр или редактор.
- Добавление, редактирование и удаление с подтверждением.
- Гранаты: название, откуда/куда, способ броска из списка или свой вариант, скриншоты и дополнительные заметки.
- Три стартовых места для скриншотов, добавление дополнительных, удаление и изменение порядка. На странице материала изображения показаны по порядку и открываются крупно.
- Способ броска накладывается по центру снизу на скриншот прицеливания, в том числе в увеличенном просмотре. Оригинальные файлы не изменяются.
- Лайнапы: одна общая позиция и несколько вариантов. Каждый вариант содержит цель, способ броска, отдельный слот прицеливания и слот результата; варианты можно переставлять и удалять.
- Свои категории создаются прямо в редакторе, относятся к выбранной карте и имеют тип «гранаты», «заметки и тактики» или «лайнапы». Категория и материал сохраняются вместе; отмена не создаёт пустую категорию.
- Теги создаются в форме, отображаются на карточках и участвуют в поиске. Нажатие на тег фильтрует список. Незавершённый ввод тега фиксируется при сохранении материала.
- Закрепление материалов, команд и прицелов вверху соответствующих списков. Закреплённые материалы сохраняют сортировку по дате изменения; снятие закрепления возвращает обычный порядок.
- Позиции, тактики и фишки: название, изображения, Markdown с предпросмотром, списками и таблицами.
- Поиск по названию, позициям, способу броска, тегам, целям лайнапов и описанию; на главной — по всей библиотеке, внутри карты/категории — в выбранном разделе.
- Консольные команды: название, текст, копирование, редактирование и удаление. Команды не выполняются приложением.
- Прицелы: скриншот и код импорта без названия, копирование кода, редактирование, закрепление и удаление. Проверяется формат `CSGO-xxxxx-xxxxx-xxxxx-xxxxx-xxxxx`; проверка кода самой игрой остаётся в CS2.
- Стрельба и пики оставлены пустыми разделами.
- Настройки: русский, английский и португальский интерфейс; четыре темы — текущая dark blue, dark `#0D0D0D`, dark red `#480002`, dark green `#233C00`. Настройки сохраняются сразу и восстанавливаются после перезапуска.
- Предоставленные логотипы используются в интерфейсе и иконке окна, в соответствии с темой. EXE использует синюю версию логотипа. SVG конвертируются в PNG/ICO при сборке без изменения рисунка.
- В настройках отображаются версия, разработчик Rockky666 и кнопка открытия репозитория GitHub в системном браузере.
- Адаптивная вёрстка, хлебные крошки, предупреждение о несохранённых изменениях.
- Экспорт/импорт всей библиотеки вместе со скриншотами, категориями, тегами, закреплениями, прицелами, способами броска и настройками.

Плитки карт используют предоставленные фотографии. Внутри каждой карты есть вкладки «Материалы» и «Карта»: во второй показывается схема с названиями позиций, обычная или альтернативная. Все изображения находятся в `public/assets` и доступны офлайн. Для Ancient предоставлена только основная схема; переключатель альтернативной версии отключён с пояснением. Названия позиций, напечатанные в исходных картинках, не переводятся при смене языка интерфейса.

Связанные ссылки из Markdown пока **не реализованы**, согласно пожеланию сначала обсудить поведение. [Предложение по ссылкам и возврату к тактике](docs/INTERNAL-LINKS.md) описывает стабильные ID, кнопку вставки ссылки, историю переходов и восстановление прокрутки.

## Где данные

```text
%APPDATA%\CS2 Assistant\library.json
%APPDATA%\CS2 Assistant\library.json.bak
```

Основная база содержит материалы, команды и изображения в base64. Сохранение: проверка схемы → запись во временный файл → копия предыдущей базы → переименование. При ошибке чтения приложение показывает ошибку и не заменяет базу пустой. Импорт проверяет структуру и просит подтверждение замены. Кнопки резервного копирования находятся в разделе **Данные и резервные копии**.

`library.json.bak` — предыдущая версия, а не история изменений. Для ручного восстановления скопируйте этот файл под именем с расширением `.json` и выберите его при импорте. Для долгосрочного хранения периодически делайте экспорт в отдельную папку.

Ограничения версии 0.2: до 30 скриншотов на обычный материал; до 20 вариантов лайнапа плюс общая позиция (максимум 41 скриншот); до 8 МБ на PNG/JPG/WebP; база до 100 МБ. До 20 тегов на материал, 200 своих категорий и 100 своих способов броска. Скриншоты хранятся в исходном качестве; base64 увеличивает размер примерно на треть. Одновременно работает один экземпляр приложения.

Версия схемы — `2`. Базы и копии версии `1` читаются с автоматической миграцией в памяти: материалы, команды, заметки, идентификаторы и порядок изображений сохраняются, новые поля получают значения по умолчанию. Чтение старого файла не перезаписывает его. При первом сохранении исходная версия попадает в `library.json.bak`. Неизвестные версии и некорректные данные отклоняются; откат к приложению 0.1 требует отдельной копии базы версии 1. Настройки и категории входят в полный импорт и заменяются вместе с библиотекой.

Markdown не исполняет HTML. Удалённые изображения и переходы по ссылкам отключены: ссылки отображаются как текст, изображения добавляются файлами. Интерфейс не загружает шрифты, карты или иной контент из сети. Renderer изолирован и получает только ограниченные операции через preload, без доступа к Node.js.

## Разработка и проверки

```powershell
npm run dev           # браузерный предпросмотр; данные только в памяти
npm run check         # тесты хранения + TypeScript + production-сборка
npm run test:desktop  # проверка реального Electron в отдельной временной базе
npm run pack          # распакованное приложение в release/win-unpacked
```

Браузерный предпросмотр намеренно не использует личную библиотеку: изменения исчезают при перезагрузке; импорт и экспорт доступны в Electron. Для повседневного использования запускайте EXE или `npm start`.

Тест Electron запускается с отдельной базой версии 1 и проверяет миграцию, CRUD, скриншоты и подписи бросков, свои категории, теги, закрепления, лайнапы, прицелы, буфер обмена, все схемы карт, четыре темы, три языка, перезапуск, экспорт/импорт, отказ от повреждённого импорта и компактную вёрстку. Скриншоты проверок находятся в `output/playwright/`. Диалоги выбора файлов для резервных копий заменяются заданными ответами; IPC, хранение и интерфейс работают настоящие. Переменная `CS2_TEST_DATA_DIR` действует только в режиме разработки; личная библиотека не используется в проверках.

На момент создания `npm audit --omit=dev` не выявил уязвимостей runtime-зависимостей. Полный аудит сообщает о moderate-уязвимости в транзитивной цепочке инструментов упаковки `electron-builder → @electron/get → global-agent → roarr → sprintf-js`; она не включена в код приложения. Обновление этой цепочки оставлено до совместимого исправления upstream.

## Структура

```text
src/model.ts          Общая схема данных, карты и категории
src/App.tsx           Навигация и экраны библиотеки
src/Editor.tsx        Форма материала, скриншоты и способы броска
src/editor-model.ts  Преобразование материала между типами категорий
src/MaterialViews.tsx Карточки, просмотр материала и схемы позиций
src/CollectionEditors.tsx Формы команд и прицелов
src/ImageFields.tsx   Загрузка файлов и слоты скриншотов
src/Settings.tsx      Настройки интерфейса и резервные копии
src/messages.ts      Полные переводы RU / EN / PT, включая диалоги Electron
src/assets.ts        Карты, варианты схем и логотипы
src/components.tsx    Markdown и модальные окна
src/storage.ts        Ограниченный мост к Electron / режим предпросмотра
src/styles.css        Тёмная тема и адаптивная вёрстка
electron/main.ts      Окно приложения, IPC, резервные копии, буфер обмена
electron/preload.ts   Публичный API для renderer
electron/storage.ts   Проверка, чтение и атомарная запись базы
tests/                Тесты данных и хранения
scripts/              Сборка Electron и проверка приложения
public/assets/        Предоставленные фотографии, схемы и логотипы
docs/SPEC.md          Исходное техническое задание
docs/INTERNAL-LINKS.md План ссылок между материалами (без реализации)
```
